## The Three Geometries

The theory rests on three geometric pillars:

1. **Geometry of Order** (Vol I): Transitive Reduction → Lorentz invariance. The Hasse diagram encodes causal structure; counting elements in an Alexandrov set reproduces the volume element. *Code:* `diamond.rs`.

2. **Geometry of Matter** (Vol II): Causal Prism K₂,ₙ → mass hierarchy. Topological defects carry quantized topological mass N and are classified into exactly three generations by the Kuratowski limit. *Code:* `skyrmion.rs`.

3. **Geometry of Logic**: O(N) scaling ⟺ physical locality. Bounded Hasse degree (D ≤ 15) implies that every topological operation is local, yielding **provably linear** O(N) complexity. This is not an engineering optimisation but a *computational proof* that the theory encodes physical locality as an information principle. *Code:* 2-hop candidate search in `skyrmion.rs`; single-pass streaming in `diamond.rs`.

## The Physics in One Page

### What is a causal set?

Spacetime is not a continuous manifold but a **discrete partial order** — a directed acyclic graph (DAG) where each node is a spacetime event and each edge encodes causal influence: A → B means "A can causally influence B." The DAG is generated by Poisson sprinkling N points into a 4D causal diamond (|t| + r ≤ T/2) with fundamental density ρ ≈ 1.

### What is a Hasse diagram?

The **transitive reduction** of the causal DAG. If A → B → C, then the direct edge A → C is redundant and removed. The Hasse diagram retains only nearest-neighbour causal links — the skeleton of spacetime.

### What is a Causal Prism?

Matter = a topological defect with **quantized mass**. A **Causal Prism** is a K₂,ₙ bipartite structure with:
- **2 poles**: timelike-separated events (past pole u and future pole v at graph-distance ≥ 2)
- **N ≥ 3 belly nodes** (intermediates w₁, w₂, ..., wₙ): each satisfying u → wᵢ → v (children of u ∩ parents of v)
- **Topological mass = N**: the integer count of intermediate nodes

**Why can't K₄ exist?** The Hasse diagram (transitive reduction) eliminates all triangles by construction. If A→B→C with direct A→C, then A→C is removed. Therefore, K₄ (requiring 4 mutually connected nodes with 6 edges forming 4 triangles) is **mathematically impossible** in a Hasse diagram. The Causal Prism (K₂,ₙ) avoids triangles: all intermediates are mutually disconnected (guaranteed by the triangle-free property), forming a stable bipartite topology.

### What is K₅ threat absorption?

The strong force = vertex absorption preventing K₅. By Kuratowski's Theorem, a graph is non-planar iff it contains a K₅ or K₃,₃ subdivision. When a threat node connects to **both poles AND ≥ 2 intermediates** of an existing Causal Prism (which would create a K₅ when combined with edges within the Prism), it is **absorbed** into the nearest pole via vertex contraction. This preserves planarity and is a discrete analogue of colour confinement — partial Prisms (isolated poles or intermediates) cannot exist stably.

### What is spectral dimension?

Gravity = random walk return probability. The spectral dimension d_S(t) = −2 d(ln P)/d(ln t) measures how quickly a random walker returns to its starting point after t steps. On a smooth 4D manifold, d_S → 4. On the Hasse graph, the vacuum d_S diverges (boundary saturation), while Causal Prism defects stabilise d_S at a finite value — matter modifies the effective geometry.

### What is causal flux?

Electromagnetism = directed transmission probability. **Directed walkers** follow the arrow of time (cause → effect only). The transmission probability from Gen1 particles to AntiGen1 particles measures **attraction** (opposite charges); transmission from Gen1 to Gen1 measures **repulsion** (same charges).

### Execution Paths

**In-memory** (`--inmemory` or auto-selected when RAM is sufficient):
All data structures live in RAM. Realisations run in parallel via Rayon with an auto-selected concurrency limit (4 threads, or 2 for N > 10M; overridable via `--threads`). Causal Prism detection uses O(N) 2-hop local candidate search.

**Streaming** (`--stream` or auto-selected when RAM is insufficient):
Uses `scan_edges_with_analysis()` for **single-pass** streaming: degree counting, core classification, and core-edge collection are merged into one scan over the edge generator. Causal Prism detection then operates on the core-induced CSR subgraph using the same 2-hop local search. RAM usage stays under ~1.3 GB per realisation even at N = 100M. Concurrency is auto-selected by CPU count (capped at 8; overridable via `--threads`).

Mode selection is automatic based on available system RAM (via `sysinfo`), configurable via `causal_set.toml`, or overridable with `--stream`/`--inmemory` flags.

### Tier System

| Tier | Condition | Algorithm | Complexity |
|------|-----------|-----------|------------|
| Eigendecomp | N ≤ 3,000 (default; `--eigen-cutoff`) | Dense S = D⁻¹/²AD⁻¹/² eigendecomposition | O(N³) |
| Monte Carlo | N > 3,000 (default; `--eigen-cutoff`) | Lazy random walkers on CSR | O(W·t), independent of N |

## Module Guide

### `diamond.rs` — Phase 1: Vacuum Generation

Poisson sprinkling in a 4D causal diamond + Hasse diagram construction.

- **`sprinkle(n)`**: Rejection-samples N points inside |t| + r ≤ T/2 with T = (24N)^{1/4} giving density ρ ≈ 1.
- **`build_hasse_sparse()`** (N ≤ 15k): Full causal closure → sparse A² reduction. Edge (i,j) is a Hasse link iff A²[i,j] = 0.
- **`build_hasse_direct()`** (N > 15k): Direct geometric construction using the **Occupied Cell Index (OCI)** — a spatial indexing paradigm that replaces naive geometric shell enumeration (96% empty cells) with per-time-layer lists of occupied cells, queried via binary search. Phase 1 topological optimizations:
  - `MAX_CAUSAL_DEPTH = 4`: Proper-time cutoff — Hasse links beyond Δt > 4 are exponentially suppressed at ρ ≈ 1.
  - `MAX_HASSE_DEGREE = 15`: Degree cap (Valve 1) — a node with 15+ descendants has fully populated its causal shadow.
  - Alexandrov volume short-circuit (Valve 2): if every causal candidate in a dt-shell is transitively blocked (non-empty Alexandrov set), further shells have strictly larger Alexandrov volume and are guaranteed blocked. Breaks immediately when degree ≥ 1.
  - Adaptive early termination (Valve 3): 1 dry Δt-shell with zero causal candidates + ≥2 descendants triggers cutoff.
- **`stream_edges_to_file()`**: Streaming variant that writes Hasse edges to disk using a sliding window, for N too large to fit in RAM.
- **`scan_edges_sparse_ext()`**: Extended streaming scanner whose callback also receives the current `safe_threshold` for node finalization tracking.
- **`scan_edges_with_analysis()`**: **Single-pass streaming analysis** — merges degree counting, core classification, and core-edge collection into one scan. Returns `(in_deg, out_deg, is_core, directed_core_edges)`. Eliminates the two-pass bottleneck, halving wall-clock time for N > 1M.

### `skyrmion.rs` — Phase 2: Kuratowski Contraction

Pure integer topology — zero floating-point. Core identification → Causal Prism detection → K₅ threat absorption → generation classification.

1. **Core selection**: top 10% of nodes by Hasse degree.
2. **Causal Prism detection (O(N) forward-forward 2-hop search)**: For each core node u, collect 2-hop candidates by traversing u → w → v through forward successors w (children of u) and their forward successors v (grandchildren of u, future pole candidates). **Minimum valence pruning**: nodes with out-degree < `MIN_PRISM_SHARED` (3) are skipped before the 2-hop traversal, and candidate poles v with in-degree < 3 are skipped before the belly intersection. Then count belly nodes |children(u) ∩ parents(v)| using the reverse CSR for parents(v). If ≥ 3, the pair forms a Prism with topological mass N = belly size. Greedy best-partner selection maximizes N per pole. **Complexity**: O(N_core × D³). With bounded Hasse degree D ≤ 15: O(10M × 3,375) ≈ 3.4 × 10¹⁰ operations at N = 100M — minutes instead of days. **Completeness**: If u and v are poles of a timelike K_{2,N}, then every belly node w_i satisfies u → w_i → v. The path u → w_i → v guarantees v appears as a candidate of u. The forward-forward 2-hop search is provably complete. The valence guard is safe because any valid pole must have ≥ 3 children (belly nodes).
3. **K₅ threat absorption**: Any neighbor connected to both poles AND ≥ 2 intermediates of an existing Prism is absorbed into the nearest pole (vertex contraction).
4. **Generation classification**: Causal Prisms classified by bit-packed topological signature `[M₀,M₁,M₂,M₃]` (normalised bulk momentum). Most abundant = Gen1 (electron-like), second = Gen2 (muon-like), third = Gen3 (tau-like). CPT conjugate = AntiGen1 (positron-like). Topological mass N computed per generation.

### `spectral.rs` — Phase 3: Spectral Dimension

Random walk return probability measurement.

- **`spectral_dimension()`**: d_S(t) = −2 d(ln P)/d(ln t) via centred finite differences.
- **`run_walkers()`**: Lazy random walkers (50% stay, 50% move to random neighbour). Parallel via Rayon. **Strict Finitism**: all internal accumulation uses `u64` integer arithmetic; the single `f64` division `count / W` occurs only at the final return.
- **`run_transmission_walkers()`**: Directed walkers (mandatory move along causal arrow). Measures flux between particle generations. Same `u64` integer accumulation as `run_walkers`.
- **`compute_eigen()`**: Exact P(t) = N⁻¹ Σ λₖᵗ from eigendecomposition of S = D⁻¹/²AD⁻¹/².
- **`compute_monte_carlo()`** / **`compute_monte_carlo_csr()`**: Monte Carlo P(t) from random walkers. The CSR variant avoids rebuilding adjacency when it is already available from Phase 2.

### `output.rs` — Phase 4: CSV Serialisation

Writes ensemble-averaged observables to CSV. The 32-column format includes: P and d_S for vacuum, defect, Gen1–3, AntiGen1, and sterile prisms; raw and normalized causal flux; mass spectrum; and ensemble standard deviations for all d_S and flux fields (error bars, nonzero when M > 1).

### `memory.rs` — RAM-Aware Mode Selection

Detects available system RAM, estimates memory requirements, and recommends in-memory or streaming mode. Includes `estimate_streaming_memory_bytes()` for the single-pass architecture (13N + 100 MB). At N = 100M: ~1.3 GB per realisation, 2 concurrent = 2.6 GB. Configurable via `causal_set.toml`.

### `main.rs` — Orchestration

Parses `--epsilon`, `--tmax`, `--seed`, `--threads`, and `--eigen-cutoff` CLI flags. Computes walker count W via the Causal Resolution Theorem (`W = ⌈(t_max / ε)²⌉`). If no seed is provided, uses the system clock (prints the seed so runs can be reproduced). Passes W to both execution paths. Runs M independent realisations, each through Phases 1–3. Ensemble-averages P(t) across realisations, then recomputes d_S from ⟨P⟩ (averaging P first is critical because d_S is non-linear in P).

## Quick Start

Ensure the Rust toolchain is installed.

```bash
cargo build --release
```

### In-memory run (standard)

```bash
cargo run --release -- 50000 10
```

- First argument: number of spacetime events N (default: 5000)
- Second argument: ensemble realisations M (default: 10)

### Streaming run (large N, single-pass O(N))

```bash
cargo run --release -- 1000000 5 --stream
```

Forces streaming mode: single-pass edge analysis via `scan_edges_with_analysis()`, followed by O(N) 2-hop prism detection. RAM usage stays under ~1.3 GB per realisation.

### Custom walker precision

```bash
cargo run --release -- 50000 10 --inmemory --epsilon 0.05 --tmax 10
```

Overrides the Causal Resolution Theorem defaults (ε = 0.01, t_max = 15) for faster exploratory runs with fewer walkers.

### Reproducible run with explicit seed

```bash
cargo run --release -- 50000 10 --inmemory --seed 12345
```

### 16 parallel realisations on a high-RAM workstation

```bash
cargo run --release -- 10000000 20 --inmemory --threads 16
```

### Force eigendecomp up to N=5000 for exact comparison

```bash
cargo run --release -- 5000 10 --inmemory --eigen-cutoff 5000
```

### Custom output directory

```bash
cargo run --release -- 50000 10 /path/to/output
```

### CLI Flags Reference

| Flag | Type | Default | Effect |
|------|------|---------|--------|
| `--seed <u64>` | u64 | system clock | Base seed. Each realisation uses `seed + i`. |
| `--threads <usize>` | usize | auto (2–8) | Max parallel realisations |
| `--epsilon <f64>` | f64 | 0.01 | Topological error tolerance ε |
| `--tmax <usize>` | usize | 15 | Maximum diffusion time |
| `--eigen-cutoff <N>` | usize | 3000 | N ≤ cutoff uses exact eigendecomp |
| `--inmemory` | flag | auto | Force in-memory mode |
| `--stream` | flag | auto | Force streaming mode |

## Expected Results

### Spectral Dimension

- **Vacuum (global)**: d_S diverges toward ~15.79 at late diffusion times (boundary saturation of the unstructured bulk).
- **Defect (with Causal Prism matter)**: d_S stabilises at ~8.36 (topological retention — the Prism bipartite structure traps probability flow).
- **Coupling constant**: α_trans ≈ 0.31, consistent with the observed strong coupling at the tau mass scale.

### Generation Classification

Causal Prisms are classified by their topological signature (normalised bulk momentum vector) and have quantized topological mass N. The simulation typically identifies 3 distinct generations plus antimatter:

| Generation | Physics Analogue | Signature | Topological Mass |
|-----------|------------------|-----------|------------------|
| Gen1 | Electron-like | Most abundant [M₀,M₁,M₂,M₃] | N ≈ 3 (light) |
| Gen2 | Muon-like | Second most abundant | N ≈ 4 (medium) |
| Gen3 | Tau-like | Third most abundant | N ≈ 5 (heavy) |
| AntiGen1 | Positron-like | CPT conjugate of Gen1 | N ≈ 3 (same as Gen1) |

### Precision Limits & Signal-to-Noise Ratio (SNR)

**Critical Note for High-N Runs:**
The precision of the topological mass measurement is limited by the Monte Carlo variance of the random walkers, scaling as $1/\sqrt{W}$ (where $W$ is the number of walkers), not just by the graph size $N$.

- The confining potential $V_{strong}$ is calculated from the log-ratio of probabilities: $V \propto -\ln(P_{def}/P_{vac})$.
- For massive ensembles ($N > 10^8$), the structural signal becomes very fine.
- **Guideline:** Walker count is now governed by the Causal Resolution Theorem: $W = \lceil (t_{max} / \varepsilon)^2 \rceil$. The default ε = 0.01 yields W = 2,250,000, sufficient for fine mass splitting at any N. For exploratory runs, `--epsilon 0.1` reduces W to 22,500.

### Causal Flux

Directed walker transmission probabilities measure electromagnetic-like interactions:
- **Attraction**: Gen1 → AntiGen1 (opposite charge, positive flux)
- **Repulsion**: Gen1 → Gen1 (same charge, lower transmission)
- **Normalized flux** (`Flux_Attr_Norm`, `Flux_Repu_Norm`): Raw flux divided by target count, isolating intrinsic per-node coupling strength (Conjecture C3).

### Sterile Prisms (Dark Matter Candidates — Conjecture C6)

Prisms with N > 5 intermediates are classified as "sterile" — gravitationally active (they contribute to d_S) but electromagnetically silent (they don't participate in Gen1–3/AntiGen1 flux). The simulation tracks:
- **P_Sterile / dS_Sterile**: Spectral dimension from walkers starting on sterile nodes.
- **count_sterile / avg_mass_sterile**: Population and average topological mass in `topology_summary.csv`.

### Ensemble Error Bars

When M > 1, the ensemble averaging computes population standard deviations for all d_S(t) and flux(t) fields. The `_std` columns in `results.csv` provide error bars for publication figures (use `mean ± std` with `fill_between` in matplotlib).

## Troubleshooting

### Linux (Arch/Ubuntu/Debian)

If compilation fails due to missing system headers, ensure you have the essential build tools.

On Arch:

```bash
sudo pacman -S base-devel
```

On Ubuntu/Debian:

```bash
sudo apt update && sudo apt install build-essential
```

### macOS

You must have the Xcode Command Line Tools installed. If you see an error regarding `cc` or the linker, run:

```bash
xcode-select --install
```

Note: The simulation is optimised for Apple Silicon (M1/M2/M3) and will utilise the efficient cores for background Monte Carlo threads.

### Windows

Install Visual Studio Build Tools 2022 and ensure the "Desktop development with C++" workload is checked.

If you encounter path issues with `cargo`, ensure you are using the **x64 Native Tools Command Prompt for VS 2022**.

Performance note: Windows Defender may slow down file I/O during `.csv` generation. Adding an exclusion for the project folder is recommended.
